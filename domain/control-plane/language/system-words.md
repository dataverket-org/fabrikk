# Words beneath the story

*Part of [the glossary](README.md).* These are not words of the story: no event on the board uses them, and [avoided terms](avoided.md) still says to use *organisation* where *tenant* is meant. They are the system's own words that design-level pages need, defined once here so that every design page can point at this page, and a word not in it is a finding. Industry terms are reused where one exists.

| Term | Meaning |
|---|---|
| **Tenant** | The system's unit of isolation: one per organisation, identified by the organisation id. The installation's organisation and every provider are tenants like any other, see [the provider as a tenant](../decisions/provider-tenant.md); whether an organisation is a provider is an agreement's fact, not the tenant's, so a tenant has no kind. |
| **Account** | The messaging system's wall around one tenant: nothing inside it is visible outside except by a declared export. One per tenant, and one that is no tenant's, the front desk. The glossary avoids *account* for a login for this reason. |
| **Export, import** | The declared way a message crosses from one account into another. The commands and integration events of [the integration contract](../decisions/integration-contract.md) are the only exports, each between an organisation's account and its provider's, between an organisation's account and the installation's, or from the front desk into the installation's. |
| **Pinned** | An instance that serves exactly one tenant, fixed at startup. An organisation-pinned instance rejects any message naming another organisation; a provider-pinned instance accepts a message naming any organisation with an agreement at this provider, arriving on that organisation's declared export; an instance pinned to the installation's organisation accepts a message naming any organisation of the installation, arriving on its export or from the front desk; each rejects the rest. Every instance is pinned to a tenant except admission and Tenancy. |
| **Service** | A unit of Dataverket software that fabrikk builds and a provider runs, named in Norwegian tradition, Sentral and Identitet among them. Holds one or more contexts. A product is built from one or more services, and some services, Sentral among them, are sold in no product. The engineering word; the business word is *product*, see [products and the catalogue](products.md). |
| **Instance** | One running copy of a context's software, pinned to one tenant: Tenancy brings it up for that tenant and gives it an identity naming the tenant, which is what admission places it by. A service runs as one or more instances. *Instance* is also Zitadel's word for the whole; the model keeps it for now, see [known tensions](../../open.md#known-tensions). |
| **Identity provider** | What admission trusts to say who a connection is, a user or an instance, and what issues a user's delegation within the user's session. The installation's, beside admission; it takes a person's login from any of the outside identity providers the installation allows, and a login is all it learns from them: validation is Person's. Never a word of the story. |
| **Admission** | Placing a connection in exactly one account after the connecting party has been identified: a user by the identity provider, placed in the organisation the person is entering, where its login has a user, or at the front desk when it enters none; an instance by the identity Tenancy gave it, which names its tenant. Admission reads from the tenants entry that the tenant exists and grants the one permission every connection has, to speak as the one actor it identified; what that actor may say is authorisation's. As in admission control. |
| **The installation's account** | The installation organisation's account: where admission and Tenancy run, pinned to no tenant, beside Person, Catalogue and the installation's Audit, pinned to its tenant. Owned by the installation's organisation, and owning it, with the front desk, is what tells that organisation apart from any provider, see [who's who](who.md). |
| **Front desk** | The account where visitors stand: no tenant's, owned by the installation's organisation. It imports the catalogue entry and exports three commands into the installation's account, *accept installation terms*, *validate* and *create organisation*; the first two an organisation's account exports too, so that a login accepts the terms and validates from wherever it is. What it admits is the installation organisation's policy, enforced at authorisation where the commands enter: [the first message](../design/tenancy/first-message.md). The lobby, in the design's earlier word. |
| **Taxonomy** | The classes of subject that authorisation is asked about: the command, event and query patterns of each service, and a connection's own reply subject. Named so that *catalogue* stays the domain's: the Catalogue context is a product catalogue in the established sense. |
| **Command class** | One of four classes the system sorts every command about an organisation's resources into, so that an organisation policy can be written without any product's words: *ask*, a command that asks a product for a thing; *operate*, one that changes a thing held; *give back*, one that ends or releases a thing held; *read*, a query. A product sorts each of its commands into a class in its announcement; the product's instance authorises a command by its class against the organisation policy. The owner's commands on the organisation itself fall into no class, and the control plane has no commands to sort. A suspension, if one returns, refuses *ask*, *operate* and *give back* and never *read*, an open hotspot in [the seam](../../method/seam.md). |
| **Condition for activation** | One of a closed list of things an agreement may wait on between its birth and *Agreement activated*; a provider names in its organisation policy which apply, and the agreement is active once every named condition is met, at once where none is named. Today the list has one, *approval*, met by the operator's *approve agreement*; the money story adds a billing entity. An agreement with a condition unmet is *held*. Rules: [Organisation's policies](../design/organisation/policies.md). |
| **Command** | What a user or a context asks a context to do, in the imperative; answered by a reply, recorded by the receiver's event, and audited with its outcome. Stack's word. Where a product reports to a control-plane context it sends that context's command, see [the seam decision](../decisions/seam-languages.md). |
| **Reply** | The answer a command receives, in the commander's shape: done or refused, with the ids the commander needs and nothing else. Distinct from the integration event the receiver publishes about the same moment, which is the receiver's own and in its own language; a saga waits for replies, a reader for events. Audited as the command's outcome, never as an entry of its own. Stack's word, from his sagas. |
| **Policy** | A context reacting to an event, its own or an imported one, with no one asking. Stack's word; the organisation's rules are always *organisation policy*, see [who's who](who.md). |
| **Read model** | What a context keeps for someone to read: a view for humans through the API, or a projection, or a published entry. Stack's word. |
| **Projection** | A read model fed by another context's integration events, keyed by the identity the events carry, see [reads between contexts](../decisions/reads.md). Stack's word. |
| **Published entry** | State a context publishes for others to read, a full snapshot per key; Evans' published language in the shape [reads between contexts](../decisions/reads.md) prefers. |
| **Aggregate** | The facts one command changes together under one set of invariants; the consistency boundary. Stack's and Evans' word. |
| **Domain event** | A fact an aggregate records for its own context; unaudited and invisible to other contexts. |
| **Integration event** | A fact a context publishes for other contexts, the published contract, named after its aggregate, versioned and audited. |
| **Saga** | A workflow across contexts with one owner, which commands, waits for the replies and runs the compensations when it is cancelled or fails. Stack's word. |
| **Gate** | A rule that must hold before an event may happen; the control plane's are in [its timeline](../story/timeline/gates.md), each product's in its own. |
| **Authorisation** | Deciding whether a sender may send this command, made by the instance that receives it, against the actor the message arrived as, the delegation it carries if any, the role in the organisation and, where the organisation policy requires a validated login for that role, the login's validation: a role whose requirement is unmet is held and does not apply, and a command in it is refused with no event. The front desk's commands are authorised where they enter, against Person's facts: the installation's terms accepted, the login's validation and the count of organisations the person is an owner in. A command the provider sends onto an organisation or into the catalogue is authorised against the operator duty, held only as the provider's organisation policy grants it. |
| **Actor** | The party a message is from, a user or an instance, as admission identified it on the connection the message arrived on. Never written by the sender: a connection speaks as exactly one actor. A message claiming another actor than the one its connection speaks as, or carrying a delegation that names another, is refused by the instance that receives it, and the refusal is audited with the connection's actor as initiator. Written into the audit entry. |
| **Delegation** | A user's proven grant to a named actor to send on their behalf, with a validity, issued by the identity provider within the user's own session for the actor the user is addressing; commanding an actor is the user's allowing, and no separate consent exists. A command sent on a user's behalf carries it; the receiver honours it only when it names the actor the message arrived as, and the audit entry names both. |
| **Envelope** | The attributes around a payload that every message carries: its own identity, the organisation it concerns, the actor as admission established it, a delegation when the command is sent on a user's behalf, the type and the schema. What names a party is never the sender's to write: the organisation is told by the crossing, the actor by admission, the person id and the terms' identity on *create organisation* by authorisation from Person's facts, and the provider on an announcement by the export it arrived on. A message naming another than these tell is refused and audited. |
| **Seam** | The places where a product meets the control plane, each a published language in one direction or the other; the list is [the seam](../../method/seam.md). The model's own word. |
